POST/validate Validate NIC · extract DOB, gender & age▾

Full NIC validation. Returns validity, date of birth, gender, age, and format. Supports both old (9+V/X) and new (12-digit) formats.

ParameterTypeRequiredDescription
nicstringrequiredOld format e.g. 881234567V or new format e.g. 198812345678
 
curl -X POST https://api.lankanicapi.lk/validate \
  -H "Content-Type: application/json" \

POST/gender Lightweight — extract gender only from a NIC▾

A lightweight endpoint that extracts only the gender encoded in the NIC without performing full date-of-birth calculation. Use this when you only need gender — it's faster and consumes fewer resources.

ParameterTypeRequiredDescription
nicstringrequiredAny valid Sri Lankan NIC — old or new format
 
curl -X POST https://api.lankanicapi.lk/gender \
  -H "Content-Type: application/json" \
  -H "X-API-Key: lnic_your_key_here" \
  -d '{"nic":"881234567V"}'

# Response
{ "valid":true, "nic":"881234567V", "format":"old", "gender":"Male" }

# New format female example
curl ... -d '{"nic":"200068700123"}'
{ "valid":true, "nic":"200068700123", "format":"new", "gender":"Female" }
import requests
def get_gender(nic, api_key):
    res = requests.post("https://api.lankanicapi.lk/gender",
        headers={"X-API-Key":api_key}, json={"nic":nic})
    data = res.json()
    return data["gender"]  # "Male" or "Female"

gender = get_gender("881234567V", "lnic_your_key")

POST/verify Verify NIC matches a date of birth — KYC▾

Cross-checks the DOB encoded in a NIC against a date provided by the user. Returns match: true or match: false. Designed for customer KYC and onboarding flows.

ParameterTypeRequiredDescription
nicstringrequiredThe NIC number to verify
date_of_birthstringrequiredDate in YYYY-MM-DD format
 
curl -X POST https://api.lankanicapi.lk/verify \
  -H "Content-Type: application/json" \
  -H "X-API-Key: lnic_your_key_here" \
  -d '{"nic":"881234567V","date_of_birth":"1988-05-02"}'

# Response
{ "nic":"881234567V", "match":true,
  "nic_date_of_birth":"1988-05-02", "provided_date_of_birth":"1988-05-02",
  "gender":"Male", "age":36 }
def verify_nic(nic, dob, api_key):
    res = requests.post("https://api.lankanicapi.lk/verify",
        headers={"X-API-Key":api_key},
        json={"nic":nic,"date_of_birth":dob})
    return res.json()["match"]  # True or False

FAQ

Frequently asked questions

What NIC formats are supported?▾
Both formats are fully supported. The old format is 9 digits followed by V or X (e.g. 881234567V), issued before 2016. The new format is 12 digits (e.g. 198812345678), issued from 2016 onwards. The API detects the format automatically.
What is the difference between /validate and /gender?▾
/validate performs a full decode of the NIC — it returns date of birth, gender, age, and format. /gender is a lightweight endpoint that returns only the gender, which is slightly faster and more efficient when that's all you need. Both count equally toward your monthly quota.
How accurate is the date of birth extraction?▾
100% accurate and deterministic. The NIC directly encodes the year, day-of-year, and gender using the official Sri Lankan standard. Our implementation correctly handles leap years, the female gender offset of 500, and all edge cases in the encoding.
Does the API store the NIC numbers I send?▾
NIC numbers are stored in request logs for debugging and analytics, retained for 30 days and tied to your API key. If your compliance requirements prohibit this, contact our Enterprise team for a zero data retention or on-premise option.
What does the free plan's 200 request limit mean?▾
Each call to any API endpoint counts as one request. The free plan allows up to 200 total requests. This is ideal for development, testing, or low-volume use cases. If you need more, reach out about our Enterprise plan for unlimited access.
What if I lose my API key?▾
API keys are shown only once at registration for security. If you lose yours, email support@lankanicapi.lk from your registered address. We'll revoke the old key and issue a new one — your plan and usage history will be preserved.
Can this be used for KYC / AML compliance?▾
Yes. The /verify endpoint is designed for this — it confirms whether a NIC matches a provided date of birth. Note that this validates NIC structure and encoded data only; it does not query government databases. For full AML compliance, combine this with your existing document verification processes.
